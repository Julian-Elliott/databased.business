## 01 · The premise

When a bank refuses someone credit, the law in most jurisdictions requires a
reason in plain language. "The model said so" is not an answer. **Adverse
action notices**, GDPR-style explanations, and ECOA-style reason codes turn
interpretability from a nice-to-have into a regulatory artefact. So when the
data science team reaches for the most accurate model in the toolbox, the
question is rarely *how accurate is it?* — it's *how accurate is it, and what
can we tell the customer afterwards?*

This post puts two models on the same problem and asks both questions
in the same breath.

## 02 · Why this pairing is interesting

A linear logistic regression is the usual transparent baseline. It's easy to
explain and easy to beat. **Zero-task auto-fuzzy** (ZTAF) raises the bar:
membership functions are derived *automatically* from the data — no domain
expert priors, no manually-curated fuzzy sets — and the resulting rule base
is still legible in English. The opposite corner is **XGBoost** trained with
no apologies: hundreds of shallow trees, no monotonicity constraints,
SHAP available only as a post-hoc apology.

The interesting question isn't which one wins on AUC. It's whether the
fuzzy model gives up enough lift that nobody would bring it to a regulator —
or whether it's competitive enough that "opaque + SHAP" stops looking like
the obvious default.

## 03 · The transparent model — zero-task auto-fuzzy

ZTAF derives fuzzy membership functions for every continuous feature by
clustering on the conditional class distribution, then synthesises a rule
base where each rule is a single readable conjunction. No expert priors;
no hand-tuned sets.

A sample of rules from the trained model:

<pre><code>{`
R01 · IF credit_history IS poor AND debt_to_income IS high
       THEN default IS likely         (support 0.18, conf 0.83)

R02 · IF utilisation IS high AND tenure IS short
       AND open_inquiries IS many
       THEN default IS likely         (support 0.11, conf 0.79)

R03 · IF income IS comfortable AND utilisation IS low
       AND credit_history IS clean
       THEN default IS unlikely       (support 0.31, conf 0.94)

R04 · IF dti IS low AND tenure IS long
       THEN default IS unlikely       (support 0.22, conf 0.91)
...
R38 · IF prior_default IS recent
       THEN default IS likely         (support 0.07, conf 0.88)
`}</code></pre>

  <p>

  </p>

### Membership-function derivation

For each numeric feature the algorithm:

1. Bins observations along a 1-D grid weighted by the local default rate.
2. Fits 3–5 triangular or trapezoidal membership functions whose peaks
   coincide with class-density modes.
3. Labels each function with the nearest plain-English bucket
   (`low`, `moderate`, `high`, `extreme`) using a fixed lookup table.

The result is reproducible, configuration-free, and surprisingly stable
across resampled training sets.

## 04 · The opaque model — XGBoost

XGBoost is the obvious counter-example: a strong baseline for tabular
classification with effectively zero interpretability out of the box.

Feature importances were collected via gain, and SHAP values were computed
on the test set for the explainability post-mortem. Both are reported, but
the framing matters: SHAP is **commentary on a decision that has already
been made**, not the decision itself.

### Calibration is the sleeper

AUC differences are easy to defend in a paper. What matters in deployment
is whether the probabilities are honest. Reliability diagrams (forthcoming
chart) show the fuzzy model is *better calibrated above 0.6* — exactly the
region where adverse-action thresholds sit. That nuance gets buried if you
only quote AUC.

## 06 · The trade

The temptation is to say "pick the higher AUC and explain it with SHAP".
The temptation is wrong roughly as often as it is right. A decision frame
that has held up across three prototypes:

|                          | high regulatory exposure | low regulatory exposure |
| ------------------------ | ------------------------ | ----------------------- |
| **small AUC gap (&lt;3 pts)** | auto-fuzzy               | auto-fuzzy              |
| **large AUC gap (&gt;5 pts)** | auto-fuzzy + shadow xgb  | xgboost + shap          |

In a credit-default setting the gap-and-exposure cell almost always lands
in the top row. Where the regulator can ask "why this customer?" you
cannot afford an explanation that won't survive cross-examination.

## 07 · What I'd ship

A two-model deployment, both trained on the same features:

- **Decisioning surface:** the auto-fuzzy classifier. Its output and the
  set of firing rules go straight into the adverse-action notice.
- **Shadow monitor:** the XGBoost model runs alongside, scoring every
  application. Disagreement above a threshold raises a manual review flag.
  This isolates the lift from the explanation, and surfaces edge cases the
  rule base hasn't learned to handle yet.

Over time, persistent disagreements feed back into the rule synthesis,
narrowing the gap without quietly migrating decisioning into an
unexplainable model.
